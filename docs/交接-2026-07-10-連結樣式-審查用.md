## 2. 已完成且驗收通過:Note Composer 拆分 ✅

**功能**:編輯器選取數個區塊 → 抽成一個新子頁 → 原地留下 `[[頁面連結]]`。對應使用者看到的 Obsidian「Note Composer」概念圖。

**後端** [Code.js](../Code.js) `api_createPageWithContent(parentId, title, contentJson)`:用既有 `createPage_` 帶內容建子頁 + `upsertText_`(讓新頁可搜尋),回 `pub_()`。

**前端** [index.html](../index.html):
- 頂欄「拆分」按鈕(id `composeBtn`),用 **mousedown + preventDefault** 觸發 `composeExtract()`。
- **核心陷阱(已解)**:Editor.js 的跨區塊選取(整塊藍底 `.ce-block--selected`)會在按鈕 mousedown 的 **capture 階段**就被清掉,按下當下讀不到選取。解法:在編輯器 `mouseup`/`keyup` 當下先把選取範圍**快照**成 `lastSelRange`,按鈕再用快照。`readSelRange()` 優先讀 `.ce-block--selected` class,退回原生文字選取。換頁時 `mountEditor` 會清 `lastSelRange`。
- 流程:切出選取區塊 → 建新子頁 → 先在 `hi+1` 插連結段、再由高往低刪 `lo..hi`(避免刪空觸發 Editor.js 自動補空塊的索引錯亂)→ 併入 `pages` map + 展開父頁 + `markDirty`/`flushSave`。標題自動取選取第一塊純文字(≤60 字),不用 `prompt()`(嵌 Google Sites iframe 會被擋)。

**部署**:A 版 @21(push -f + redeploy 主部署),B 版已同步並驗收。**未動 renderShare_ → 不用 manifest dance;無新服務 → 不用改 oauthScopes。**

## 3. 已移除:日曆 🗑(規劃審查重點)

**做了什麼又拿掉**:本場先實作了完整日曆(月曆格子標出哪天有每日筆記、點格子開/建當天筆記,沿用既有「每日筆記」自動頁系統),後端 `api_calendarMonth`/`api_openOrCreateDaily` + 重構 `dailyPageJob` 出 `dailyParentId_`/`dailyTitle_`/`dailyBlocks_`,前端 `#calView` 面板 + `showCalendar` 等。**之後應使用者決定,整包乾淨移除**,程式碼回到 = A 版 @21。

**為什麼移除**:日曆靠**標題前綴 `yyyy/MM/dd`** 認每日筆記,改標題就失聯,使用者覺得綁定方式微妙;加上策略轉為暫停。

**若未來要復活(給 Fable 5 評估)**:建議別再綁標題。三個選項:
- A(原做法)標題前綴:零成本、脆。
- **B(推薦)另開小表 `DailyMap(date, pageId)`**:建每日筆記時寫一列,日曆讀這張。跟標題脫鉤,**又不動 PageIndex/Trash 那組耦合**(見 HANDOFF 的 INDEX_HEADER↔TRASH_HEADER 地雷)。
- C:PageIndex 加日期欄:查詢最快,但要連動改 TRASH_HEADER,侵入性高、風險大。

日曆的完整實作已在 git 歷史中被移除,若要復活可從本手冊描述重建,或翻對話。

## 4. 待確認驗收:外部連結自動化 ⚠️(只動 index.html)

**功能**:貼上單一網址 → 自動變藍色可點連結、清掉常見追蹤參數(`fbclid`/`utm_*`/`gclid` 等);點外部連結開新分頁。

**實作**:
- CSS `#editor a[href^="http"]`:藍色底線、長網址自動換行。
- 擴充既有 editor `click` handler:`#page=` 走內部導頁;`http(s)` 走 `window.open(href,'_blank','noopener')`(**不依賴 target 屬性是否被 Editor.js sanitize 保留**)。
- editor `paste` handler(**capture 階段** `true`):剪貼簿是單一 URL 才攔截,程式碼區塊/表格/既有連結內不處理。`cleanUrl()` 用 `URL` API 移除追蹤參數。
- **刻意不做**載入時把既有純文字網址轉連結(那會影響所有頁面、blast radius 大、又無法本地測)。既有醜連結需**重新貼一次**才會自動化。

**狀態**:程式已 commit(`12bbec8`)。**部署/驗收未回報,B 版未同步。**

## 5. 待確認驗收:文字顏色 / 字級 ⚠️🔴 風險最高(只動 index.html)

**功能**:選字後 Editor.js 行內工具列出現 🎨,點開有 8 色 + 四段字級(小/中/大/特大)+「清除」。

**實作**:
- `class StyleTool`(定義在 `mountEditor` 之前),註冊為 `tools.style = { class: StyleTool }`。
- **關鍵**:`static get sanitize() { return { span: { style: true } }; }` —— 否則 Editor.js 存檔會把帶樣式的 `<span>` 濾掉。
- 沿用官方 LinkTool 模式:`render()` 給按鈕、`surround(range)` 存 `this.range` 並切換 `renderActions()` 面板顯示、色票/字級按鈕用 `mousedown+preventDefault` + `this.range` 做 `extractContents`/`insertNode` 包 span、`this.api.inlineToolbar.close()` 收工具列。

**這段無法本地測、Editor.js 行內工具 API 細節多,是本場最高風險。請 Fable 5 重點審查 + 請使用者實測。三個失敗情境要分辨**:
- 🎨 有出現但**點了沒反應** → `surround`/`range` 有問題。
- 顏色/字級有變但**重新整理後消失** → `sanitize` 沒吃到(span 被濾)。
- 🎨 **完全沒出現** → 工具註冊有問題。

**狀態**:程式已 commit(`12bbec8`)。**部署/驗收未回報,B 版未同步。**
